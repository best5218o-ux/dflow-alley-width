## 3. A — 회전 기하 산식

### 3-1. 노드 진입각(편향각) θ

- 노드 N 에서 T_NODE = N 인 진입 링크 a, F_NODE = N 인 진출 링크 b 의 모든 쌍 (a ≠ b).
- 방향벡터: a 는 **마지막 선분**(끝 두 정점), b 는 **첫 선분**(첫 두 정점). 선분 길이 0 은 다음 정점으로 넘어간다.
- θ = 두 벡터 사잇각(0° = 직진, 180° = 되돌아감). 단위 도(°).

### 3-2. 방향쌍 제외 규칙 (003 §3-3)

아래 중 하나면 **회전으로 세지 않고 제외 건수만 기록**한다.

1. b 의 T_NODE = a 의 F_NODE (같은 두 노드를 되짚는 역방향)
2. a·b 의 `ROAD_NAME` 이 같고(빈칸 아님) θ ≥ 150°

### 3-3. 링크 내 최소 곡률반경 R_link

- 링크 선형을 **호 길이 10 m 간격으로 재표본화**(양 끝점 포함).
- 연속 세 점의 외접원 반지름을 모두 구해 **최솟값**을 R_link 로 한다. 세 점이 일직선이면 ∞.
- 링크 길이 < 20 m 이면 세 점이 성립하지 않으므로 **NOT_COMPUTED**.
- 정점 디지타이징 잡음이 10 m 척도 아래로 들어오지 않게 하려는 규칙이며, 실제 도로 곡선반경의 **근사**다.

### 3-4. 「판정이 필요한 급회전」 정의 — 사전 고정

| 대상 | 정의 |
|---|---|
| **노드 급회전 이동** | 3-2 제외 후 θ ≥ **90°** |
| **링크 급곡선** | R_link < **12 m** (규칙 대형자동차 최소회전반지름) |
| 보조 구간표 | θ: 0–30 · 30–60 · 60–90 · 90–120 · 120–150 · 150–180 / R_link: <7 · 7–12 · 12–15 · 15–30 · 30–60 · ≥60 — **전 구간을 모두 보고**(임계 하나만 고르지 않음) |

- 「급회전」 = **판정이 필요하다**는 뜻이지 「통과 불가」가 아니다.
- **판정 가능 여부**: 해당 지점의 도로 폭(또는 모서리 가용 공간) 값이 있어야 판정 가능. 표준노드링크에는 폭 속성이 없다 → **판정 가능 0 · 증거등급 D**.

### 3-5. 요구 폭 W_req(turn) — 정상원 회전 기준 상한

단일 차체 차량이 최소회전반지름으로 회전할 때 차체가 쓰는 폭(스웹트 패스 폭):

```
R_or = sqrt(R² − L²)              뒤축 바깥 바퀴 궤적 반지름
R_ir = R_or − B                   뒤축 안쪽 바퀴 궤적 반지름
R_oc = sqrt(R_or² + (L + F)²)     차체 앞 바깥 모서리 궤적 반지름
W_req(turn) = R_oc − R_ir
```

- 가정: 규칙 표의 「최소회전 반지름」을 **바깥 앞바퀴 궤적 반지름**으로 해석한다(규칙 표에 정의가 없음 — **해석 가정**으로 명기).
- 회전각이 정상원에 이르지 않으면 실제 폭은 이보다 작다 → 이 값은 **상한(보수측)**.
- 차종별 값: R·L·F 공란 → **공란**. 규칙 설계기준자동차 3종 값만 계산한다.
- 링크 급곡선에는 규칙 제22조① **확폭량 표**(설계기준자동차별 R 구간)를 **참고로 병기**한다. 표 범위 밖(대형자동차 R < 15 m)은 「규칙 표 범위 밖」으로 적는다.

### 3-6. 집계 단위

- 전국 / 대상지 4곳(브이월드 검색 API 동 대표점 반경 500 m, 노드 좌표 기준) — **대상지 값은 반경 500 m 탐색창 값이며 도시 대표값이 아니다.**
- 세는 단위: 급회전 **이동 수** · 급회전 이동이 1개 이상인 **노드 수** · 급곡선 **링크 수**. 방향별 링크 이중 계수는 해소하지 않고 그대로 적는다(001 §8-3).

## 4. B — 진입곤란 37개소 역검증

### 4-1. 좌표화 (사전 고정)

- 「구간 세부현황」에서 괄호 안 설명을 떼고 `~` `,` `/` 로 조각낸다. 조각마다 「일원」「일대」 등 꼬리말 제거, 「서구」 등 앞말 제거, 「○○로 N번길」의 공백 제거.
- 조각에 「산」 또는 「번지」가 있으면 브이월드 지오코더 `type=parcel`, 아니면 `type=road`. 앞에 「대전광역시 {시군구}」를 붙인다(시군구 열 `대덕`→대덕구, `유성`→유성구).
- **개소 성공** = 조각 1개 이상 좌표 반환. 개소 좌표 = 성공 조각 좌표 전부(점 집합).
- 검증: SHP 34 선형과 상세명(괄호 안 문구)으로 짝지어, 지오코딩 점에서 해당 선형까지 거리를 잰다.

### 4-2. 링크 매칭

- 조각 좌표마다 **최근접 링크**(거리 무제한, 전 링크 대상). 매칭 거리와 `ROAD_NAME` 이 조각 도로명과 같은지 기록.
- 37개소 링크 집합 = 매칭 링크의 합집합.

### 4-3. 「기하적으로 구별되지 않는 구간」 기준 — 사전 고정

링크 특징(폭 불요):

| 특징 | 정의 |
|---|---|
| f1 최대 진입각 | 링크 양 끝 노드에서 이 링크가 진입 또는 진출인 이동(3-2 제외 후)의 θ 최댓값 |
| f2 R_link | 3-3 (NOT_COMPUTED 는 비교에서 조건 충족으로 치지 않음) |
| f3 LANES | 편도 차로수 |
| f4 ROAD_RANK | 도로 등급 코드 |

기준(37개소 매칭 링크 분포에서 산출 — **분위수는 매칭 링크 기준, 선형 보간**):

- **C1** f1 ≥ 37개소 f1 의 **25백분위수**
- **C2** f3 ≤ 37개소 f3 의 **최댓값**
- **C3** f4 ∈ 37개소 f4 **값 집합**
- **구별되지 않음** = 대전 권역(권역코드 183–187) 링크 중 **C1 AND C2 AND C3** 를 만족하고 37개소 링크 집합에 **들지 않는** 링크
- f2 는 37개소 매칭 링크의 NOT_COMPUTED 비율이 50% 를 넘으면 기준에서 뺀다(짧은 링크가 많아 분포가 서지 않으므로). 50% 이하면 **C4** f2 ≤ 37개소 f2 의 75백분위수 를 AND 로 더한다. **어느 쪽인지 결과 문서에 적는다.**
- 결과 서술: 「37개소와 기하적으로 구별되지 않는 링크가 대전에 N개 더 있고, 그 N개를 판정할 폭 데이터가 없다.」 — 「행정이 놓친 곳」 표현 금지.
- 방향별 링크 이중 계수는 링크 수로 그대로 적고, 같은 이름·반대 방향 짝 제거 후 수(도로 구간 근사)를 **병기**한다.

## 4-1-v2. 좌표화 규칙 개정 (2026-09-15, v1 실행 후 · B 링크 매칭 전)

**개정 사유(v1 결과에서 확인된 오류 — v1 결과는 지우지 않고 함께 보고한다)**
- 도로명 줄기가 없는 조각(「30번길」「46번길」「134번길」)이 엉뚱한 도로로 해석됨: 예) 연번 10 「30번길」 → 가수원중로47번길 30
- 지오코더가 다른 도로로 보정한 결과도 status OK: 연번 21 홍도로55번길 → 홍도로113번길 55(공간정보 선형에서 631.1 m), 연번 34 송리로1번길 → 송리로14번길 1(282.2 m)

**v2 규칙 (추가만 하고 v1 의 나머지는 유지)**
1. **줄기 상속**: 조각이 숫자+「번길/번안길/길」로만 되어 있으면 같은 행 **직전 조각의 도로명 줄기**(「○○로」「○○길」까지)를 붙인다. 예) 갈마중로28번길, 30번길 → 갈마중로30번길
2. **도로명 일치 검증**: 지오코더 `refined` 문자열에서 시군구 뒤 첫 도로명 토큰을 뽑아, 조각의 도로명(공백 제거)과 **완전히 같을 때만** 조각 성공으로 인정. 지번(`parcel`) 조각은 동·리 이름이 refined 에 들어 있으면 인정
3. 개소 성공 = v2 인정 조각 1개 이상. **B 링크 매칭(§4-2)은 v2 인정 조각만 쓴다**
4. 보고: v1(좌표 반환) · v2(도로명 일치) 성공 수를 **나란히** 적는다

§4-3 「구별되지 않음」 기준(C1~C4)은 **바꾸지 않는다.**

## 5. C — 이태원 권역 시공간 슬롯 배정 시연: 시나리오·규칙 사전 고정 (실행 전 커밋)

> **이 절의 수요·용량 수치는 전부 시나리오 파라미터다. 측정값이 아니다.** 사건은 `SYNTHETIC_EVENT` 로 표기한다.
> 인구 격자(연번 13)는 **미수급**이라 대피 수요를 격자에서 만들지 않는다 — 운집 규모를 파라미터로 둔다.

### 5-1. 공간·그래프

- 권역: 이태원동 브이월드 검색 API 동 대표점 반경 **700 m** 안에 **양 끝 노드가 모두 있는** 표준노드링크.
- 그래프·경로탐색·결정기록·재계산 버전은 **공통엔진 `DFlowCore`(DFLOW_008R9R4_CORE)** 를 import 해서 쓴다. 공통엔진에 없는 기능(칸 용량·충돌해소 5단계·지연 장부·2-hop 범위)은 시연 스크립트에 두고 **capability 변경요청으로 기록**한다.
- 사건 지점: 동 대표점 **최근접 링크의 종점 노드**. 긴급차량 출발: 권역 경계 노드 중 `ROAD_RANK` 가 가장 높은(코드값 최소) 링크에 접한 노드 1개(동률이면 NODE_ID 오름차순 첫째).
- 대피 목적지: 사건 지점에서 그래프 거리가 가장 먼 권역 경계 노드(보행 유출 방향의 대리값 — 대피소 데이터 미사용 시).

### 5-2. 통과판정 — 회전 기하 축만 적용, 폭 축 D 잠금

- **긴급차량 경로**는 θ ≥ 90° 이동(§3-4 급회전)을 **잠금(증거등급 D · 판정 보류)** 하고 `route_candidates` 의 `edge_blocked`/`turn_bans` 훅으로 제외한다. 잠긴 이동은 **전부 장부에 남긴다.**
- 폭 축: 모든 링크 `width_status = D`(속성 부재). 배정 결과는 **RECOMMEND_ONLY · 현장 확인 필요**로만 낸다. 잠금 때문에 경로가 없으면 **「미해소 — 판정 보류로 경로 없음」**으로 표시하고 대체하지 않는다.
- 보행·일반차량 경로는 회전 잠금을 적용하지 않는다(차량 제원 판정 대상 아님).

| 우선순위 | 고정 5단계(원고 2-5): ① 인명안전(대피 보행) 확정 → ② 긴급차량: 대체 경로가 잠금 없이 존재하고 지연 증가 ≤ 1칸이면 경로 이동, 아니면 칸 뒤로 → ③ 일반차량: 뒤 칸 이동(최대 2칸) → ④ 조건부 카드(자동 실행 안 함) → ⑤ 미해소 표시 |
| 지연 | 칸 이동 1칸 = 10분. 총지연 · 주체별 지연 · 최대 개인 지연 |
| 재계산 트리거 | t2 에 「돌발 통제」 1건 — **긴급차량 확정 경로 위 링크 중 LINK_ID 오름차순 첫째**를 용량 0 으로. 재배정은 그 링크 **2-hop 이내** 레코드만, 밖은 잠금 유지. 재배정 대상·유지 대상 레코드 수를 로그로 남김 |

### 5-4. 산출

- 해소 전/후 간트(충돌이 가장 많은 링크 3~4개 × 6칸), 지연 장부, 미해소 칸 목록, 잠긴 이동 목록, 재계산 로그, `DecisionRecord` 버전 사슬.

### 5-5. 보완 (실행 전 · §5-3 에서 빠진 항목만 채움)

- 경계 노드 = 권역 안 노드 중, 권역 밖 노드와 이어진 링크가 하나라도 있는 노드. NODE_ID 오름차순 정렬.
- 일반차량 1: 경계 노드 첫째 → 마지막 / 일반차량 2: 둘째 → 끝에서 둘째. 사건 지점 링크(동 대표점 최근접 링크)는 **통제**로 보고 경로에서 제외(`edge_blocked`).
- 구급차 3대 출발 = 펌프차 출발 노드와 같음.
- 이동 시간 모형: 한 주체는 **출발 칸에 경로 전 링크를 동시에 점유**(10분 칸 ≫ 권역 통과 시간이라는 단순화 — 결과 문서에 명기).
- `DecisionRecord`: baseline_route = 잠금 없는 최단경로, emergency_route = 급회전 잠금 경로. emergency_route 가 없으면 공통엔진 계약상 기록이 거부되므로 **기록하지 않고 장부에 「미해소 — 계약상 결정기록 불가」**로 남긴다.
- 해소 순서 안 동률은 주체 ID 오름차순.

### 5-6. 2번째 arm — 「사람 확인 후 해제」 (1번째 arm 실행 후 · 2번째 실행 전 커밋)

**1번째 arm(엄격 fail-closed) 결과는 그대로 주 결과다**: 긴급차량 4대 전부 급회전 잠금으로 경로 없음 → 미해소, 공통엔진이 결정기록 4건을 계약 위반으로 거부, 재계산 트리거 미발생.

2번째 arm 은 설계상 흐름(잠금 → **사람 확인 요청** → 확인된 이동만 해제)을 시연한다. 수치를 고르기 위한 기준 변경이 아니다.

- 해제 대상: **긴급차량 baseline 경로가 지나는 잠긴 이동만**(1번째 arm 기록: `1020003004:1020010702->1020011904` · `1020020003:1020009502->1020008801`, 2개). 다른 잠금 30개는 유지.
- 해제 사유 표기: 「지휘관 현장 확인(가정) — 폭 값은 여전히 없음, 증거등급 D 유지, RECOMMEND_ONLY」.
- 그 밖의 시나리오·파라미터·해소 규칙·재계산 트리거는 §5-3~5-5 그대로.
- 결과 보고: 두 arm 을 **나란히** 적는다. 2번째 arm 의 수치를 1번째 arm 없이 인용하지 않는다.

## 6. C 3안 — SOP 200 제3장 3.1 적용 (CONTEST-VWORLD-004 §6-5) · 실행 전 커밋

근거 조문: 소방청, 재난현장 표준작전절차, 2026.5, SOP 200 화재대응 공통 표준작전절차 제3장 3.1(원문 p.37). **3.1 본문 단서 「특별한 사정이 있는 경우에는 현장 상황에 맞게 배치할 수 있다」에 따라, 3안의 대기 배치는 지휘관 판단의 입력(권고)이다.**

### 6-1. 전제 — 2안과 비교 가능하게

- 권역·사건 지점·주체·시간 칸·대피 흐름·일반차량·재계산 트리거·2안의 사람 확인 해제 2건은 **2안과 같다.**
- 슬롯 3종: **진입**(경로 링크, 진입 칸 1칸) · **전개**(펌프차가 사건 링크 1차로를 진입 칸부터 t5 까지) · **대기**(후착 차량이 대기 링크 1차로를 진입 칸부터 t5 까지).
- 적용 범위 확장(명기): SOP 3.1.2 는 「후착대 소방차량」 조문이다. 시나리오에는 후착 차량이 구급차 3대뿐이므로 **R2 를 후착 긴급차량에 적용**한다 — 조문의 적용 대상을 넓힌 시나리오 가정이다.

### 6-2. R1 · R2 · R3

- **R1 펌프차 우선 진입**: 긴급차량 해소 순서에서 펌프차(선착) → 구급차(후착).
- **R2 대기 링크 선정 = SOP 3.1.2.1 · 3.1.1.1 조건**
  - 후보: 사건 링크에서 무방향 링크 인접 기준 **1~3 hop** 링크(사건 링크 제외).
  - 조건 판정 표:

| # | 조문 | 판정식 | 입력 | 판정 가능성 | 적용 |
|---|---|---|---|---|---|
| 1 | 회차에 용이한 장소(3.1.2.1) | 회전 기하 + 가용 폭 | 노드링크, **폭 없음** | **보류 D** | **필터로 쓰지 않는다.** 모든 대기 레코드에 「회차 용이: 판정 보류(D) — 지휘관 확인 필요」를 **잠금 사유로 기록** |
| 2 | 소화전 인근(3.1.2.1) | 대기 링크 중점 ↔ 가장 가까운 소방용수시설 거리 **최소** | 서울 소방용수시설(2025-12-31, 좌표 이상치 제외) | 계산 가능 | **순위 1순위** |
| 3 | 선착대 소방차량 퇴각에 장애 없음(3.1.2.1) | 대기 링크 ∉ 펌프차 경로 링크 ∪ 전개 링크 | 경로 산출 | 계산 가능 | 필터 |
| 4 | 특수 소방차량 진입에 장애 없음(3.1.2.1) | 대기 점유 후 **잔여 차로 ≥ 1**(LANES − 대기 대수 ≥ 1, 대기 칸 전부) | LANES(편도, 결측 0%) · 폭 없음 | **부분 C** | 필터 |
| 5 | 후착대 배치 공간 고려(3.1.1.1) | 대기 링크 ≠ 선착 전개 링크 · 전개 링크의 인접 링크면 잔여 차로 ≥ 1 을 한 번 더 확인 | 경로 + 차로수 | **부분 C** | 필터 |

  - 순위: ② 소화전 거리 오름차순 → 사건 링크까지 hop 수 오름차순 → **LINK_ID 오름차순**(링크 식별자, 차량 ID 아님).
  - 후보가 없으면 그 후착 차량은 **대기 미해소**로 표시(대체하지 않음).
- **R3 동점 처리 — 차량 ID 순 금지**
  - 같은 우선순위(구급차 3대)가 같은 칸을 다투면 **칸마다 수용 가능한 대수만큼 동시 배정**하고 나머지는 다음 칸. 누가 먼저인지는 **정하지 않는다** — 지연은 차량별 이름이 아니라 **지연 분포(예: 10·20·30분 각 1대)** 로만 보고한다.
  - 대기 링크도 같은 방식: 순위표 위에서부터 채우며, 어느 구급차가 어느 링크인지는 표시하지 않는다(대기 링크 ID · 대기 대수 · 대기시간만).

### 6-3. 소방용수시설 입력

- 원천: 서울열린데이터광장 OA-21306 「서울시 소방재난본부_소방용수시설_20251231.csv」(data.go.kr 15146212 경유, 로그인 불요)
- 인코딩 cp949, 해석 불가 바이트는 대체 문자로 읽음(대체 26자 — 좌표 열 무관)
- 좌표: 위도 33–39 · 경도 124–132 밖은 제외하고 건수 기록. `시설유형코드` 는 의미 정의가 파일에 없어 **구분하지 않고 전부** 쓴다. `사용가능여부` 는 전 행 빈칸 — 사용 가능 여부를 판정하지 않는다(거리만).

### 6-4. 산출

총지연 · 주체별 지연 · 최대 개인 지연 · **펌프차 진입 칸 변화(2안 대비)** · **대기 링크 ID와 대기 대수·대기시간** · **대기 점유가 일반차량 우회에 준 영향(일반차량 1 배정 칸·지연 2안 대비, 대기 링크와 경로 교차 여부)** · **SOP 5개 조건 판정/보류 내역** · 재계산 트리거(2안과 같은 규칙) 로그.

## 7. C 3안 관측 입력 연결 — [B] 3종 (CONTEST-VWORLD-004 §17) · 실행 전 커밋

3안(§6) 규칙은 그대로 두고 **입력 세 가지만** 관측 개방데이터로 바꾼다. 연결 순서 B2 → B3 → B1, 매 단계 3안 재실행.
일반차량 **수요 규모(대수·기종점)는 시나리오 파라미터로 남는다**(개방데이터에 통행량 없음 — 교통소통정보는 속도·통행시간만).

### 7-1. B2 돌발상황 — 재계산 트리거 실입력

- 원천: 국가교통정보센터 돌발상황 일 단위 파일 2026-09-08 ~ 2026-09-14(7일, 로그인 불요)
- 선택: `링크아이디` ∈ 이태원 권역 그래프 링크(표준노드링크 2026-09-14, 반경 700 m) — 선택 결과 전부 사용, 거르지 않음
- 해석: **단일 링크 이벤트**. 통제 구간(구간 폐쇄)으로 해석하지 않는다. 링크 차단·용량 차감을 하지 않는다
- 모형 적용: 3안의 합성 트리거(「t2, 긴급차량 경로 링크 중 LINK_ID 최소」)를 **폐기**하고, 선택된 이벤트 링크마다 3안과 같은 재계산 범위 분석(2-hop · 범위 안 레코드 · 그 링크를 쓰는 레코드)을 한다. 발생 시각은 기록대로 보존하되 **시나리오 칸 대응은 t2**(시나리오 가정). 재배정은 하지 않는다(3안과 같음)
- 선택 0건이면 「미확인」

### 7-2. B3 서울 생활인구 — 인파 수요의 시간 분포

- 원천: 서울 열린데이터광장 OA-14991 행정동 단위 서울 생활인구(내국인) 2026-07(31일 × 24 시간대)
- 행정동: **11170650 이태원1동 · 11170660 이태원2동** — 코드↔동명은 서울시 상권분석서비스(점포-행정동, OA-22172, 행정안전부 주민등록 행정기관코드) 파일로 대조
- 산출: 시간대 h 의 두 동 합계를 31일 평균 → P(h). **상대값 r(h) = P(h) / median_h P(h)** 만 쓴다. 절대 인원은 쓰지 않는다(행정동 → 700 m 권역 안분은 하지 않음. 한다면 증거등급 C)
- 모형 적용(가정, 증거등급 C): 대피 보행 점유 칸 수 n(h) = clamp(round(2 × r(h)), 1, 5). 3안 합성값 2칸은 r = 1(중앙값 시각)에 대응시킨다
- 실행 시각: 시나리오 시각 **20시** 1회 + 감도 1회(**r(h) 최대 시각**). 두 결과를 모두 보고하고 유리한 쪽을 고르지 않는다

### 7-3. B1 교통소통정보 — 일반차량 칸 용량 속도 보정

- 원천: 국가교통정보센터 교통소통정보 일 단위 5분 파일 **2026-09-14**(로그인 불요) — 권역 그래프 링크만 추출
- 칸 대응: 칸 s(10분) = 20:00 + 10·s 분, 칸의 관측 속도 v_obs(e,s) = 그 10분 안 5분 속도 평균
- 기준 속도 v_ref(e) = 같은 링크 당일 5분 속도 **95분위**
- 보정: k = min(1, v_obs / v_ref) · **일반차량 칸 용량 = round(LANES × k)**(0 이상). 긴급차량 진입·대기·전개 칸 용량은 보정하지 않는다(LANES 그대로)
- 파일에 없는 링크·칸은 보정하지 않고(LANES) 「속도 미수록」 개수를 기록한다
- 수록 링크 0개면 「미확인」

### 7-4. 산출

단계별(3안 → +B2 → +B3 → +B1) 총지연 · 최대 개인 지연 · 펌프차 진입 칸 · 대기 링크 · 미해소 · 재계산 범위 · 관측 입력 수록률. 도표 4 는 3안(합성) 대 최종 단계를 비교한다.

### 16-5. 추가 기준 — 첫 결과(건수 구성비)를 본 뒤 추가함 (2026-09-16, 실행 전 커밋)

첫 실행(§16-1~4 그대로) 결과를 보고 드러난 편향 두 가지 때문에 **측정을 추가**한다. §16-1~4 의 건수 결과는 바꾸지 않고 함께 보고한다.

1. **분절 단위 편향** — 도로명주소도로는 도로명 하나가 긴 구간 하나인 경우가 많고, 표준노드링크는 교차로마다 링크가 끊긴다(방향별 2개 포함). 건수 구성비는 이 분절 방식에 끌려간다 → **길이 구성비**를 추가: 표준노드링크 `LENGTH`(m) 합, 도로명주소도로 `road_lt` 합(단위 미확인 — 명세 없음). 각 원천 안 위계별 길이 비율만 비교
2. **「번길」 이름 관행** — 도로명 부여 방식이 지역마다 달라(서울 등은 「…로N길」 식) 「번길」 비율이 시도마다 크게 벌어진다. 「번길」은 골목 위계의 대리 지표로 **충분하지 않다** → 가지도로 비교를 **「길+번길」 합산** 으로도 적는다
3. **시도 결합 방식 변경** — `lt_c_adsido` 가 섬 폴리곤 포함 1,000건 상한에 걸려 전 링크 공간 결합이 불가. 대신 표준노드링크 `LINK_ID` 앞 3자리마다 링크 20개(균등 표본)의 중점을 브이월드 `lt_c_adsido` 에 점 조회해 시도를 정하고, **20개가 모두 같은 시도일 때만** 그 앞자리 전체를 배정. 불일치 앞자리는 「혼재」로 두고 건수 기록
4. 도로명주소도로 시도는 `lt_c_adsido` 의 `ctprvn_cd`·`ctp_kor_nm` 로 표기(12 = 「전남광주통합특별시」 — 브이월드 광역시도 레이어 기준)

## 24. AI-A 진입곤란 분류 모델 M1·M2 (CONTEST-VWORLD-016 E · 015 §7) · 실행 전 커밋

### 24-0. 4원칙·범위

### 24-2. 특징(이름마다 브이월드 `lt_l_sprd` 대전 구간을 모아 계산 — 선형 포함 재수급, §10 격자·키 sig_cd+rds_man_no)

### 24-3. 방법
- 분류기 1(주): 로지스틱 회귀 — 표준화, L2, C=1.0, class_weight=balanced, max_iter=2000
- 분류기 2(보조): 랜덤포레스트 — 500 트리, min_samples_leaf=5, class_weight=balanced_subsample, random_state=0
- 평가: **구 단위 Leave-One-Group-Out(5겹)**. 겹마다 학습 → 시험 구 확률 → 전체 OOF 확률로 지표 계산

- **원천**(둘 다 연속수치지형도 1:5,000, 브이월드 WFS): **표고점 `lt_p_n3f0020000`**(속성 `nume` 표고) · **등고선 `lt_l_n3f0010000`**(속성 `cont` 등고수치 · `divi_nm` 구분). 조회 실패는 「미조회」로 적는다
- **대상** = §29 와 같은 대전 진입곤란 26개소 37조각. 축선은 §29-2 와 동일(조각 지점 최근접 도로중심선의 도로경계 면 안 구간, 양 끝 2 m 절단)

### 33-1. 산출 방법 — 두 가지를 각각 내고 병기한다(합치지 않는다)
- **P 표고점 회귀**: 축선 버퍼 40 m 안 표고점을 모아 축선 진행거리 s 에 대한 표고 z 의 **최소제곱 기울기**를 종단경사로 본다. **표고점 3개 미만이면 `NOT_COMPUTED`**
- **C 등고선 교차**: 축선과 등고선의 교차점을 모아 (최대 cont − 최소 cont) / (교차점 간 축선 거리) 를 종단경사로 본다. **교차 2개 미만이면 `NOT_COMPUTED`**
- **조각의 면 안 축선 길이가 등고선 간격보다 짧으면 C 는 `NOT_COMPUTED`**(짧은 조각에서 등고선 보간은 의미가 없다)
- 등고선 간격은 조회된 `cont` 값들의 최소 차이로 **실측해 기록**한다. 수직 정확도는 원천 문서에서 확인되면 적고, 확인 못 하면 **「수직 정확도 미확인」**으로 적는다
- 경사는 **% (고저차/수평거리 × 100)** 로 적고 부호는 절댓값을 쓴다(진행 방향을 정하지 않았다)

### 33-2. 판정 — 기준이 없으면 판정하지 않는다
- **소방차 등판능력 기준값**을 공개 문서에서 확인하면 출처·문서명·조항을 그대로 적고 그 값으로 판정한다
- **확인하지 못하면 37조각 전부 `UNKNOWN_FAIL_CLOSED(기준 미확보)`** 로 두고 값만 참고로 적는다. **추정하지 않는다. 일반 상용차 기준을 빌려 쓰지 않는다**(용수 도달성에서 호스 연장 기준을 못 찾아 전부 UNKNOWN 으로 둔 것과 같은 처리)

### 33-3. 등급
- 폭 축과 같은 규칙(어긋나지 않음 0.8 이상 C · 0.5 이상 D · 미만 E) · **B 이상 금지**
- **경사에는 사람 판독 대조군이 없다.** 대조 상대가 없으면 등급을 주지 않고 **「대조 불가」**로 둔다
- P 와 C 두 방법의 값이 서로 어긋나면 그대로 적는다(한쪽을 고르지 않는다)

### 33-4. 4원칙

- 대체설명: 표고점 밀도·등고선 간격·조각 길이가 값에 미치는 영향을 함께 적는다

## 34. 주차차량 차감 통행가능폭 — SAM 차량탐지 + 도로구간 회랑 (CONTEST-VWORLD-057) · 실행 전 커밋
- **§25(노면 분할 측정, 실패)는 그대로 둔다.** §34 는 같은 모델로 **주차 차량**을 찾아 공공데이터 `road_bt` 에서 **횡방향 점유폭을 차감**한다
- 이름: 산출값은 **「해당 촬영 시점의 통행가능폭 추정」**(증거등급 C, 촬영 시점 타일 미표기 — 미확인, 실시간 아님)

### 34-1. 대상
- **적용셋** = 26개소 도로명 조각 37(§8 · `missing_alley_crosscheck.json` road 조각)
- **검증셋** = 사람 판독 11조각(`ortho_readings.json`) — 학습·조정에 쓰지 않는다. SAM 사전학습 가중치 그대로, 파라미터 조정 없음

### 34-2. 입력
- 영상: 브이월드 WMTS Satellite **z19** · `data/vworld/ortho_cache/` 캐시 우선, 없으면 `VWORLD_APIKEY` 로 수급
- GSD = `156543.03392 × cos(위도) / 2^19` 를 **조각 위도로 각각** 계산(상수 금지) · 업샘플 **UP = 3**(쌍삼차)
- 회랑 기준선: `data/vworld/national/raw/daejeon_sprd_geom.jsonl` 의 **같은 도로명 `rn`**(공백 제거 비교) 도로구간 선형(EPSG:5186 → 4326 → z19 화소). 같은 도로명 행이 여럿이면 **조각 좌표에 가장 가까운 행**을 쓰고 그 행의 `road_bt` 를 그 조각의 폭으로 쓴다
- **적용셋 작업창**: 그 행 선형 위 조각 최근접점을 중심으로 원영상 **256×256 px**(정북 정렬) → UP 3
- **검증셋 대조창(§34-표 3 전용)**: §25-2 와 같게 **선형 방향 가로 정렬 · 가로 ±16 m · 세로 ±12 m** → UP 3

### 34-3. 마스크 생성
`SamAutomaticMaskGenerator(points_per_side=32, pred_iou_thresh=0.86, stability_score_thresh=0.90, min_mask_region_area=300)` · ViT-B · 로컬 CPU · 조정 없음

### 34-4. 차량 규격 선험 (사전 고정 · 근거 등급: 사전 가정, 공개 기준 미확보 — 문헌 인용으로 쓰지 않는다)
마스크 최대 외곽의 최소외접직사각형 기준. 장변 L · 단변 S · 면적 A(마스크 화소 수) · 직사각도 R = A/(L·S)
- 3.0 ≤ A ≤ 20.0 ㎡ · 3.0 ≤ L ≤ 7.5 m · 1.4 ≤ S ≤ 2.8 m · 1.6 ≤ L/S ≤ 4.2 · R ≥ 0.62

### 34-5. 회랑 필터 (공간정보 = 정밀화 단계)
- 회랑 = 34-2 선형을 **`road_bt`/2** 로 버퍼한 면(작업창 화소 좌표) · **최소외접직사각형 중심**이 회랑 안이면 회랑 통과
- **확정 차량 = 규격 선험 통과 ∧ 회랑 통과**. 「규격만 통과·회랑 밖」 = 오탐 제거 수 · 오탐 제거율 = 오탐 제거 수 / 규격 통과 수

### 34-6. 횡방향 점유폭
- 마스크 외곽점을 선형에 투영한 지점의 진행 방향에 **수직인 축**으로 외곽점을 사영해 **최대 − 최소**(m)
- 조각 대푯값 = 확정 차량 횡점유 **중앙값** · 최악값 = **최대값**

### 34-7. 산식·판정
- **W_pass = road_bt − 횡점유 중앙값** · **W_worst = road_bt − 횡점유 최대값**(병기 필수)
- 판정은 **§29-5 밴드 그대로, W_worst 로 한다**: ≤ 2.5 `BLOCKED`(문헌) · ≤ 3.5 `CONDITIONAL_C`(우리 설정, 근거 문헌 미확보) · 그 외 `폭축_통과후보`. W_pass 는 병기만

### 34-8. FAIL_CLOSED
- 같은 도로명 행 없음 / `road_bt` 없음 → `UNKNOWN_FAIL_CLOSED`
- 확정 차량 0 이고 **사람 판독 `parked_vehicles_seen` ≥ 1**(수 또는 「여러 대」 문구) → `UNKNOWN_FAIL_CLOSED_미탐`. road_bt 를 통행가능폭으로 쓰지 않는다
- 확정 차량 0 이고 사람 판독 0 대 또는 판독 없음 → `차량없음_road_bt적용`(W_pass = W_worst = road_bt, 「통과」로 쓰지 않는다)

### 34-9. 증거등급
- 영상 판독 기반 **C** · 「현재 통행가능폭」이 아니라 **「해당 촬영 시점의 통행가능폭 추정」** — 표 제목·본문에 병기

### 34-10. 분리 방식 판정 (W_worst)
- **긴급차량 전폭 E** — KFS 「3.3 제원」 전폭 상한을 원문에서 읽는다: 소방펌프차 KFS 0008 경형 1.9 · 소형 2.2 · 중형·대형 2.5 / 물탱크차 0009 · 화학차 0010 · 사다리차 0011 · 굴절차 0012 = 2.5(m 이하). **조각의 E = W_worst 이하인 전폭 상한 중 가장 큰 값**(그 폭에 보낼 수 있는 가장 큰 차급 — 차종 판정과 같은 규칙, 보수적)
- **보행자 유효폭 P = 1.2 m** — 장애인등편의법 시행규칙 [별표 1] **1. 장애인등의 통행이 가능한 접근로 가.(1)** 「접근로의 유효폭은 1.2미터 이상」. 같은 항 (2)의 교행구역 1.5 m×1.5 m 는 「설치할 수 있다」(임의)이고, 접근로에는 완화값(부득이한 경우 값)이 없다 — 원칙값 1.2 를 쓴다
- **일반차량 전폭 G = 2.0 m** — 「도로의 구조·시설 기준에 관한 규칙」 제5조 설계기준자동차 **소형자동차 폭 2.0**
- 판정: **W_worst ≥ E + P → 공간 분리** · **E ≤ W_worst < E + P → 시간 분리** · **W_worst < 1.9(가장 작은 전폭 상한) → 통과 불가** · `UNKNOWN_FAIL_CLOSED*` → **판정 보류**
- **일반차량 진입차단 필요 = Y** : 판정 보류가 아니고 W_worst < E + G (통과 불가 조각은 Y)
- `차량없음_road_bt적용` 조각도 같은 규칙으로 판정하되 비고에 「road_bt 기준 · 차량 미탐 가능」을 적는다
